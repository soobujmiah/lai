## Source audit

- **Inference and models:** `AppContainer` composes native llama.cpp; `MainViewModel` builds a role-tagged conversation, applies the user turn window, then counts template tokens and trims oldest turns to fit context. `llama_session.cpp` applies the GGUF model's chat template, tokenizes with llama.cpp, reuses KV prefix, prefills, samples, decodes, and streams UTF-8 through `native_inference.cpp`/`NativeInferenceEngine`. The reviewed catalog pins Qwen 2.5 1.5B Q4_K_M and Q4_0 with hashes and backend compatibility. CPU is the only shipping default.
- **Parameters and response correctness:** UI settings drive max output tokens, temperature, top-p and seed. The native sampler applied top-p *before* repetition penalties. This can exclude alternatives before repeated tokens are penalized; the order is corrected. UTF-8 accumulation before JNI callback, stream backpressure, chat history and context trimming were inspected and no separate confirmed corruption was found. Missing/incorrect model chat-template metadata, quantization or inherently weak 1.5B Bangla generation remain possible causes of poor replies. This code finding is **not** proof that every bad response is fixed; comparison with identical prompts/settings/seed and owner device evidence remains necessary.
- **Accelerators:** CPU, Vulkan, OpenCL and Hexagon share a native backend registry. The scheduler requires explicit evidence for accelerators, with an empty set in ordinary builds. Two 2026-09-04 Hexagon qualification passes exist, but default promotion is not justified. OpenCL still stalls in `clGetPlatformIDs` after the main-thread hang fix. Vulkan on Redmi Turbo 4 Pro (`onyx`) loaded and completed prefill, then reproducibly SIGSEGV'd inside vendor `vkCmdBindPipeline` at first decode. The available evidence does not isolate a failed pipeline handle, shader, synchronization fault or driver bug to a single cause. A native SIGSEGV cannot be caught by Kotlin fallback. The known-crashing onyx path is now rejected before session creation, allowing normal CPU selection. GPU remains unqualified; a new upstream fix and owner-operated device validation are required before lifting this guard.
- **Android and CI:** `runtime:ocr` previously returned `OcrModelRequiredException`; `AgentRuntime.runOcr` already captures a screenshot, calls the engine, serializes `OcrResult`, and recycles the bitmap. GitHub Actions runs source policy, JVM/Android unit tests, lint and the signed release APK build. No model or APK binary is committed.
