# OpenCL Qualification Runbook

## Purpose

Provide a one-action device-side diagnostic export so qualification does not require the operator to manually collect many shell commands and logcat fragments.

## In-app diagnostic export

The diagnostic build should expose a **GPU / Diagnostics → Export qualification bundle** action. One tap must collect a timestamped, self-contained archive containing:

- LAI package/version and process identity.
- Current Android UID/GID as evidence only; never persist it as a stable identifier.
- SELinux process context.
- `/dev/kgsl-3d0` existence, mode, SELinux label and open/read/write result.
- Adreno model and readable KGSL properties.
- Qualcomm GPU driver package/path and relevant Android GPU properties.
- Presence, mode, SELinux labels and ELF dependencies of Qualcomm OpenCL/Vulkan libraries.
- Direct native OpenCL probe result.
- LAI GPU probe logs captured by the application itself.
- A bounded system-log snapshot where Android permissions allow it.
- Build/device metadata needed to reproduce the qualification environment.
- A single timestamped JSON manifest containing pass/fail status for every probe stage.

## Export format

Prefer a single `.zip` generated by the app's private/cache storage and shared through Android's standard `ACTION_SEND` / `FileProvider` flow. The archive should contain:

```text
lai-gpu-diagnostics-<timestamp>.zip
├── manifest.json
├── device.json
├── kgsl.txt
├── gpu-properties.txt
├── vendor-libraries.txt
├── opencl-probe.json
├── app-log.txt
└── system-log.txt
```

The app must never require `adb`, Termux, root, or a stable Android UID for normal export.

## Security/privacy

- Do not export passwords, tokens, API keys, model prompts, personal documents, or unrelated application data.
- Redact obvious secrets from captured logs.
- Do not attempt to disable SELinux or modify vendor files.
- Do not hard-code an Android UID; Android app UIDs can change between installs.
- System `logcat` capture is best-effort because an ordinary untrusted Android app may not be allowed to read unrestricted logs. The app should clearly mark unavailable data instead of pretending it was collected.

## Qualification sequence

`device access → native library loading → OpenCL platform enumeration → GPU enumeration → context → queue → buffer I/O → kernel test → LLM qualification`

A successful stage does not imply that later stages are supported. Only measured evidence advances the qualification state.

## Interpretation

`/dev/kgsl-3d0` access proves device-node access, not GPU compute support. Vendor library presence proves the components exist, not that the application can load or execute them. Buffer I/O validation is below full LLM qualification.

## Operator workflow

1. Install/run the diagnostic build.
2. Open **GPU / Diagnostics**.
3. Tap **Export qualification bundle**.
4. Share the generated ZIP back to the development workflow.
5. The development workflow records the manifest and relevant evidence under `docs/device-results/`.
