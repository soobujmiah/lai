# SKB Knowledge Continuity Contract

Canonical knowledge base: `soobujmiah/skb`.
Canonical entry point: `AGENT_NAVIGATION.md`.

## Start

For non-trivial LAI work, consult the minimum relevant owner/project context from SKB before material decisions. Later sessions do not require the user to repeat “read SKB” merely because the LAI repository is named.

Order: LAI local instructions/current state → SKB `AGENT_NAVIGATION.md` → minimum sufficient context → live LAI evidence.

SKB provides continuity/context. LAI-specific rules, direct evidence, higher-priority policy, and explicit human authority remain stronger.

## Return

Before handoff, review whether the session created durable facts, decisions, architecture changes, constraints, capabilities, failures, or verification evidence useful to SKB. Classify each as new, update, duplicate, contradiction, historical, uncertain, or rejected. Do not return secrets, private payloads, temporary noise, or unsupported claims.

## Adaptive engineering

SKB does not prescribe a fixed language, framework, architecture, document set, or project template. Select the best fit for LAI's actual requirements and constraints; use ADRs for material architectural changes.

## Failure

If SKB is unavailable, never invent its contents. Continue from verified LAI evidence where safe and record the missing dependency.

Legacy Mode is intentionally deferred and is not part of this contract.
